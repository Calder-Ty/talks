# Does Developer Experience Matter?

When it comes to software there have traditionally been two competing values:
the behavior value and architectural value. Behavioral value relates to
correctness, and ability of the software to actually execute useful behavior.
This value can be measured by functionality of the system compared to it's
complexity. Architectural value is the ability of software to be modified for
future requirements. This value can be measured by the marginal cost of adding a
new features to an existing system.

Over the past 10+ years there has been an introduction of a third value,
"Developer Experience". Developer Experience is often used to evaluate the
hygiene of code from a software developers perspective. Words such as
_readability_, _ergonomics_ and _clean_ are often used. Is there any objective
way to evaluate code on a Developer Experience level? And does it help make
software we can love?

The goal of this talk will be to answer these questions and hopefully provide
guidance to answering the question "What makes software users can love?".
